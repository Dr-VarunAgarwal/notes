Captain Claw on Switch

Projects · AI involvement 7/7 — AI-Generated · Filed as I go

I wanted a classic running natively on a modded Switch, not through an emulator. The first idea was an ICO port, which turned out to be the wrong size of project. Captain Claw (Monolith Productions, 1997) was a better fit, because a community engine rewrite of it already exists: OpenClaw, by pjasicek, a from-scratch C++ engine on SDL2 that reads the original game's data files.

Why not ICO.

The ICO PC port draws through Vulkan, and homebrew on the Switch does not get Vulkan. It would have needed a new renderer, a new platform layer, and no promise of playable speed. A 2D game on SDL2 only needs the toolchain and some glue.

What it took.

The build uses devkitPro (devkitA64, libnx and the Switch builds of SDL2). A Switch target went into OpenClaw's CMake files. The game runs from a folder on the SD card with your own copy of the game's data, which is not included anywhere on this page or in the build.

The rest was glue. OpenClaw only understood a keyboard, so controller buttons are translated into the key presses it expects, with a right-stick pointer and touch for its mouse-driven menus. Button layout lives in a small text file on the SD card so it can be changed.

Things I added.

  • A splash screen, icon and a credits page for everyone involved.
  • The original cutscenes, converted from the old Smacker video format into something the Switch can play simply, with the game's own Replay Movies menu switched back on.
  • A cheats menu under Options, with on-screen confirmation, and an option to unlock all levels.
  • An intro on/off switch and louder default volume.
  • A Level Guides section, still being finished: map overviews plus tips condensed from the community walkthroughs by Rich Kleinhenz.

What went wrong along the way.

A few of these were my own doing. Quitting the game crashed the Switch app until I stopped it calling the C exit function. The first menu buttons ignored the controller entirely, because the game empties its event queue while loading and my code was waiting on an event it had already thrown away. A save file corrupted itself when I unlocked a fourteenth level the engine does not actually have. Menu cursors followed file order instead of screen order. None of it was subtle once I looked, but the Switch gives no console to look at, so I added a log file to the SD card.

How it was built.

Claude (Anthropic) did most of the engineering under my direction; Gemini did bulk drafting, including the first pass of the level tips, which are marked as condensed and should be read as hints, not gospel. I tested on the hardware and kept deciding what the thing should be.

What is not done.

Level 14, the last one, does not work. The original game has it, and its data is all there, but OpenClaw never implemented it: it has no description file for the level and no code at all for the final boss, Lord Omar. Between-level cutscenes are not triggered automatically either; they play from the Replay Movies menu and the intro at launch.
